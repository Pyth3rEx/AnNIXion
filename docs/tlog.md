# Terminal session recording on AnNIXion

Every pentest action needs a reproducible record: the exact command, its
output, and a timestamp. `tlog-engagement` is an opt-in front door onto
[tlog](https://github.com/Scribery/tlog) for exactly that — start it, work a
session, and the whole thing lands as structured JSON you can replay, grep,
or push straight into [SysReptor](sysreptor.md) as evidence.

---

## Why it is vendored

`tlog` is not in nixpkgs yet — the pull request that adds it,
[NixOS/nixpkgs#571777](https://github.com/NixOS/nixpkgs/pull/571777), is still
open against `master`, and this distribution's pin is `nixos-26.05` regardless.
So `catalog/support/tlog.nix` builds it from upstream's own source directly,
the same way `catalog/c2/frameworks/adaptixc2.nix` vendors AdaptixC2.

There is also no NixOS module for it here, by choice rather than by gap.
Upstream's own module makes `tlog-rec-session` a setuid login shell that
audits every session on the box unconditionally — built for an organisation
auditing users who did not ask to be audited. That is the wrong shape for one
operator who wants to start recording *this* engagement, on demand, and have
every other terminal on the box left alone. `tlog-engagement` is that on-demand
front door instead.

## Using it

```bash
tlog-engagement start acme-2026-11          # record an interactive shell
tlog-engagement start acme-2026-11 -- nmap -sV 10.0.0.0/24   # or just one command
```

Nothing is captured until `start` runs, and only the one shell it starts —
every other terminal, and every non-interactive process on the box, is
untouched. Exit the shell (or let the given command finish) to stop
recording.

```bash
tlog-engagement list              # every recording, across every engagement
tlog-engagement list acme-2026-11 # just this engagement's
tlog-engagement play <file>       # replay one in this terminal, at real speed
```

Recordings land under
`${XDG_DATA_HOME:-$HOME/.local/share}/annixion/tlog/<engagement>/<UTC
timestamp>.tlog.json` — one JSON object per captured chunk, in [tlog's own
format](https://github.com/Scribery/tlog).

### Pushing to SysReptor

```bash
reptor conf                      # once: point reptor at a project (see sysreptor.md)
tlog-engagement push             # the recording this shell just made
tlog-engagement push <file>      # or a specific one
```

`push` hands `reptor` two things: the raw recording, as evidence you can
replay later with `tlog-play`/`tlog-engagement play`, and a plain-text
transcript — every captured chunk of output, in order, with ANSI escapes
stripped — as a note, so it is readable and greppable in the SysReptor UI
without replaying anything. It needs `reptor conf` already pointed at a
project; `push` without a path defaults to whatever this shell last recorded
(`$ANNIXION_TLOG_FILE`), falling back to the most recent recording on disk.

The transcript is generated by reading the recording's own JSON directly, not
by shelling out to `tlog-play`: `tlog-play` replays at real speed over a
live control-key read loop, which hangs indefinitely once its input hits
EOF — fine watched at a terminal, fatal run from a script.

## `--log-input`

```bash
tlog-engagement start acme-2026-11 --log-input
```

By default, only output is recorded. `--log-input` also records every
keystroke sent to the session — which can capture a password typed mid-session,
including one a prompt deliberately hid from the screen (`sudo`, `ssh`, a
login form) and would otherwise never appear anywhere in the log. Turning it
on prints a line saying so; there is no silent way to enable it.

Leave it off unless you specifically need to prove what was typed, not just
what happened.

## Where things live

```
~/.local/share/annixion/tlog/<engagement>/<timestamp>.tlog.json   # recordings
/etc/tlog/tlog-rec.conf    # empty — tlog refuses to start without one existing
/etc/tlog/tlog-play.conf   # same

catalog/support/tlog.nix   # the vendored package, the wrapper, no menu entry
system/tlog.nix            # the two config files above
```

tlog's binaries refuse to start without their own config in `/etc/tlog`, even
an empty one — `system/tlog.nix` is the whole of the system wiring that
provides it. There is nothing to configure beyond that: `tlog-engagement`
takes the engagement name and `--log-input` as arguments instead of NixOS
options, so changing either never needs a rebuild.
